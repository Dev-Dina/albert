# Implementation Plan: Memory and Router

**Branch**: `003-memory-router` | **Date**: 2026-05-26 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/003-memory-router/spec.md`

## Summary

Add Redis-backed conversation memory (per-tenant, per-conversation, TTL-expiring), an HTTP classifier router that short-circuits simple messages before they hit the full agent, and a tool-selection eval harness with 15 labelled examples wired to CI. The full inbound chat flow is wired end-to-end: redaction → guardrails pre-check → router → (agent if needed) → guardrails post-check → memory write → response.

**Scale/Scope**: Per-tenant, per-conversation; max 10 turns loaded per session

## Implementation Notes

### memory.py

- Uses `redis.asyncio.Redis` client stored on `app.state.redis`
- Key format: `conv:{tenant_id}:{conversation_id}` (string key, JSON value)
- Value: JSON list of `{"role": "user"|"assistant", "content": "..."}` turns
- Max 10 turns loaded (drop oldest when over limit)
- TTL reset on every write (`SETEX` with `settings.redis_session_ttl`)
- PII redaction: call `_redact(text)` — stub returns text unchanged; swap when Owner C delivers
- Graceful degradation: if Redis is unreachable, log warning and return empty history / skip write

### router.py

- HTTP POST to `{settings.modelserver_url}/classify` with `{"message": text}` and `Authorization: Bearer {service_auth_token}`
- Response: `{"label": str, "confidence": float}`
- If `confidence < settings.router_confidence_threshold` or `label == "ambiguous"` → return `RouterDecision(action="agent")`
- Label map (deterministic actions):
  - `"greeting"` → direct reply: "Hello! How can I help you today?"
  - `"farewell"` → direct reply: "Thank you for chatting! Goodbye."
  - `"out_of_scope"` → direct reply: "I'm only able to help with questions about this business."
  - anything else → `action="agent"`
- Fallback on any HTTP error: log warning, return `RouterDecision(action="agent")`
- Increments tenant counters: `router_handled` / `agent_handled` (stub log only until Owner A's cost tracker lands)

### chat.py (POST /chat)

Full flow:
1. Extract `tenant_id` from verified auth (stub: `X-Tenant-Id` header — same pattern as ingest.py)
2. Load conversation history from memory service
3. Apply redaction to inbound message (stub)
4. Guardrails pre-check (stub: `_guardrails_check(message)` returns `True`)
5. Call router — get `RouterDecision`
6. If `action == "direct"`: reply = `RouterDecision.reply`; if `action == "agent"`: call `run_agent()`
7. Guardrails post-check on reply (stub)
8. Write turn to memory (redacted message + reply)
9. Return `{"reply": reply, "routed_to": "router"|"agent"}`

### tool_selection_eval.py

- Loads `tool_selection.jsonl` (15 examples: `{"message": str, "expected_tool": str|null}`)
- For each: calls `run_agent()` with a mock LLM that returns the first tool call the real model would make (or use a replay approach with the real LLM)
- Simpler approach: direct unit-style check — call `_dispatch_tool` decision logic or mock agent responses
- Counts correct/total, prints per-example pass/fail
- Exits 1 if `accuracy < eval_thresholds.yaml[tool_selection_accuracy]`
